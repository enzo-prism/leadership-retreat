# Repository Guidelines

## Project Structure & Module Organization
The Next.js app lives in `app/`, with route segments mapped directly to pages and layout components. Shared UI building blocks sit in `components/`; keep reusable client components here and import with the `@/` alias. Re-usable logic, data helpers, and configuration belong in `lib/`. Static assets and Open Graph images reside in `public/`. Tailwind layer overrides are defined in `styles/`, and design tokens generated by v0 live in `components.json`.

## Build, Test, and Development Commands
- `pnpm install` — install dependencies; prefer pnpm to stay aligned with `pnpm-lock.yaml`.
- `pnpm dev` — run the local Next.js dev server with hot reload.
- `pnpm build` — create an optimized production build (surfaced in CI and Vercel previews).
- `pnpm lint` — run the ESLint suite; treat warnings as actionable before merging.

## Coding Style & Naming Conventions
TypeScript is required for app code. Follow the existing Prettier-style formatting: two-space indentation, single quotes avoided, and no trailing semicolons. Components and React hooks use PascalCase and camelCase respectively; co-locate component-specific styles and utilities when it keeps files readable. Favor Tailwind utility classes and variants; extract shared patterns into `components/ui/*` to avoid duplication. Run `pnpm lint` before commits to catch import ordering and accessibility issues.

## Testing Guidelines
Automated tests are not yet established. When adding coverage, colocate component tests as `ComponentName.test.tsx` within the relevant folder, and integration tests under `app/(segment)/__tests__/`. Use React Testing Library for component behavior and Playwright for end-to-end flows. Always run the new suite plus `pnpm lint` before submitting, and document any intentional gaps in the PR description.

## Commit & Pull Request Guidelines
Commit messages should be short, present-tense, and task-oriented (e.g., `Adjust retreat moment portrait framing`). Conventional prefixes such as `feat:` or `chore:` are welcome for clarity but not required. For pull requests, include: a brief summary of the change, screenshots or recordings for UI updates, reproduction steps for fixes, and links to related issues or design references. Highlight any synced changes pulled from v0.app to avoid review surprises.

## v0 Sync & Deployment Notes
This repository mirrors a Vercel deployment and stays in sync with edits made in v0.app. Avoid manual edits to generated design tokens unless upstreamed to v0. Verify production readiness by running `pnpm build` locally before triggering Vercel deploys, and confirm analytics or environment variable adjustments in `next.config.mjs` when applicable.
